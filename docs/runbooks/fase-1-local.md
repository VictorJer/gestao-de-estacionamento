# Executar Fase 1 localmente

Somente desenvolvimento/testes. Nenhum recurso Azure é criado. Requer Docker Desktop com daemon Linux, Docker Compose, navegador/Playwright, .NET 10 e Node 24 para testes locais. Configure uma senha temporária forte do SQL Server em `.env` (arquivo ignorado pelo Git): `ESTACIONAMENTO_SQL_PASSWORD=<senha exclusiva de teste>`. Nunca publique esse arquivo nem imprima a senha no terminal/CI. A senha de CI deve estar no segredo de repositório `FASE1_SQL_TEST_PASSWORD` antes do PR.

1. Execute `docker compose up --build -d`. O edge fica em `https://localhost:8444` (certificado autoassinado local); a API e o SQL Server não são publicados. Confira `docker compose ps` e `curl.exe -k https://localhost:8444/api/v1/session/antiforgery` (Windows). O navegador deve aceitar *somente em desenvolvimento* o certificado local. Não copie esta exceção para produção.
2. Para criar uma conta descartável, defina `ESTACIONAMENTO_TEST_USER`, `ESTACIONAMENTO_TEST_PASSWORD` (forte, não padrão) e `ESTACIONAMENTO_TEST_ROLE` (`manobrista`, `caixa` ou `administrador`) como variáveis de ambiente; execute `docker compose --profile test-user run --build --rm provision`. O provisionamento não é um endpoint público e rejeita usuários preexistentes. Guarde as credenciais em local seguro fora do repositório. `local-secrets/` é ignorado e usado pelos testes E2E de integração.
3. Em `frontend/`, execute `npm ci`, `npm test -- --watch=false` e `npm run build`. Em `backend/`, `dotnet restore Estacionamento.slnx`, `dotnet build Estacionamento.slnx` e `dotnet test Estacionamento.slnx` (Windows usa `.\\SQLEXPRESS` com banco de teste único; Linux precisa de `ESTACIONAMENTO_TEST_SQL` com SQL Server real). Em `tests/e2e/`, execute `npm ci`, `npx playwright install chromium` e `npm test`. Para E2E real, defina `ESTACIONAMENTO_EDGE_URL=https://localhost:8444` e `ESTACIONAMENTO_REAL_SESSION=1`; coloque JSON `{ "username": "...", "password": "..." }` em `local-secrets/test-credentials.json`. Opcional: `ESTACIONAMENTO_RESTART_TEST=1` reinicia a API durante o teste.
4. A API aplica migrações ao iniciar **somente** com `ASPNETCORE_ENVIRONMENT=Development` e `Database:ApplyMigrations=true` na topologia Compose. Para banco descartável local independente, configure `ConnectionStrings__DefaultConnection` para o banco exclusivo e execute `dotnet tool run dotnet-ef database update --project src/Estacionamento.Infrastructure --startup-project src/Estacionamento.Api` em `backend/`. Nunca execute migração contra banco de terceiros.
5. Reiniciar apenas o app: `docker compose restart api` ou `docker compose up --build -d api edge` para atualização; o volume `sql-data` preserva registros e `key-ring` preserva cookies existentes. Reverter o aplicativo: reimplante a imagem anterior da API/edge, preservando volumes e mantendo migrações aditivas compatíveis; não reverta dados por exclusão do banco. `docker compose stop` interrompe serviços sem apagar dados. **Não** use `down -v` em ambiente com dados que queira manter.

Não há garantia de backup/restore, continuidade ou proteção gerenciada das chaves nesta fase. Para produção são exigidas decisões e testes próprios, listados em `docs/decisions/fase-1.md`.
